# 求职诊断框架

本文件供 `job-search-diagnostic` 在目标收敛、岗位拆解、缺口排序和复查设计时使用。

## 1. 目标收敛

目标不是“想变好”，而是一个可检验的岗位选择：在什么时间、面向什么组织或岗位类型、用什么证据证明进入下一轮。

### 从三条线索收敛

1. **已验证的工作资产**：使用者已经做过什么、承担到哪一步、别人为什么愿意为结果付费。
2. **不可让步的条件**：城市、通勤、作息、薪酬底线、工作许可、家庭责任等。只问会影响岗位集合的条件。
3. **可接受的试错成本**：愿意花多久补一项能力、是否接受平级转岗、是否接受先做邻近岗位。

根据这些线索提出 2-3 条目标假设，而不是从热门职业清单里随意推荐。每条假设写明：

- 目标岗位与一个合理层级；
- 已有事实为什么指向它；
- 目前最缺的证据；
- 最小验证动作与风险。

若使用者完全说不出经历，可先让其列最近 12 个月实际交付的三件事，并说明每件事的产出、对象和结果。没有事实基础时，不生成职业方向排名。

### 目标收敛的完成条件

至少拿到一个真实岗位说明，能回答：

- 这个岗位重复交付什么结果？
- 哪些条件明确为必须项？
- 使用者现有哪项事实与该职责直接相关？
- 还缺的是门槛、证据、能力还是机会？

未满足时，下一步通常是收集并对比 3 个真实岗位说明，并选其中一个做最小证据验证。不要继续扩展成大规模职业测评。

### 多目标处理

一次只有一个主目标。使用者给出多个候选岗位时，按决策紧迫度（截止日、窗口期）选一个先诊断，其余列入待诊断队列；每个岗位各出一张诊断卡，不在一张卡里横向比较多个目标的“匹配度”。

## 2. 岗位说明拆解

### 逐句标记

| 标记 | 含义 | 示例 |
|---|---|---|
| M | 明确必须项 | “须持有教师资格证” |
| C | 核心职责 | “独立负责客户续约与风险客户干预” |
| V | 证据/验证要求 | “面试需携案例复盘”“需通过上机测试” |
| P | 优先项 | “有 SaaS 经验优先” |
| X | 语境条件 | “早期团队、需要自建流程” |
| ? | 含义不清 | “具备较强商业敏感度” |

四层拆解（硬门槛 / 核心职责 / 证据要求 / 语境条件）与符号的对应：M→硬门槛，C→核心职责，V→证据要求，X→语境条件，P 是核心职责或语境条件中的优先项，? 一律转“待确认判断”。

`M` 不自动等于不可替代，`P` 也不自动等于可以忽略。招聘方的真实筛选口径属于待确认判断。若无法向招聘方确认，就用同组织同层级的多份真实岗位说明寻找稳定要求。

### 从职责还原证据

对每项核心职责追问：

1. 这项职责会产生什么可见结果？
2. 证据里能否看出使用者自己的动作，而不只是团队结果？
3. 有没有范围和难度信息，例如客户数、周期、预算、约束？
4. 结果有无来源，是否能够复述或展示？

“参与”“协助”“负责”不是证据本身。需要继续确认决策权、执行范围和结果归属。

## 3. 证据分级

不计算总分，但标明证据能支持哪种判断。

| 等级 | 形态 | 能支持 | 限制 |
|---|---|---|---|
| 直接证据 | 本人作品、系统截图、报告、指标看板、公开成果、可运行样本 | 具体任务已实际完成及其结果 | 仍需确认个人贡献、语境和时效 |
| 书面旁证 | 主管/客户/合作方确认，绩效记录，验收单 | 第三方确认行为或结果 | 可能只覆盖部分工作 |
| 可追溯自述 | 有时间、对象、动作、结果和来源线索的案例 | 形成待核验假设，指导补证 | 不能单独证明结果归属 |
| 概括自述 | “沟通能力强”“做过项目” | 只能识别需要追问的方向 | 不进入匹配结论 |
| 空缺 | 没有相关信息 | 只说明未知 | 不能解释为能力不足 |

### 与简历对标五状态的映射

简历逐条对标使用的五种状态，按下列口径落到证据等级，防止把自述写成已核验：

| 对标状态 | 对应证据等级 | 结论口径 |
|---|---|---|
| 直接证据覆盖 | 直接证据或书面旁证 | 可写进“能证明什么” |
| 自述可覆盖（待核验） | 可追溯自述 | 只能写“待核验”，附来源线索 |
| 部分覆盖 | 可追溯自述或概括自述 | 写明覆盖哪一段、缺哪一段 |
| 未覆盖 | 空缺 | 写“当前证据未覆盖”，不写“没做过” |
| 未知 | 空缺 | 转“需要确认的判断” |

### 证据条目格式

`E01｜事实｜证据材料｜证明了什么｜来源｜日期｜限制`

每条证据尽量只证明一个核心命题。若一条材料同时证明多个命题，拆开或明确主要用途。

## 4. 缺口判定与优先级

### 五种缺口

| 缺口 | 判定 | 不应写成 |
|---|---|---|
| 目标未闭合 | 没有岗位或要求，无法定义“匹配” | “职业方向不清晰”这类人格判断 |
| 准入缺口 | 已确认的硬门槛不满足或未知 | “肯定没戏” |
| 证据缺口 | 经历可能存在，但无法证明个人动作或结果 | “能力不足” |
| 能力缺口 | 已有证据表明核心任务尚不能完成，且短期无法补足 | “缺少信心” |
| 机会约束 | 时间、地点、岗位供给或招聘窗口限制 | “不够优秀” |

### 排序规则

1. 先处理会使目标失效的准入和信息问题；
2. 再确认岗位真实要求是否被正确理解；
3. 若没有硬门槛冲突，优先补最影响招聘方判断的直接证据；
4. 只有证据显示核心任务无法完成时，才把能力建设列为 P0；
5. 资格年限、证书、地点等不可快速改变的限制，转化为换目标或替代路径，而不是泛泛努力建议。

只保留一个 P0。次要观察最多列两条，不据此增加第二个主行动。

## 5. 条件式结论

### 可投

使用条件：直接证据覆盖主要核心职责，关键个人贡献可辨，且没有已知硬门槛冲突。

仍需写明：证据限制、待确认判断、投递后的复查触发点。

### 补证后投递

使用条件：没有已知硬门槛冲突；存在一项会显著改变筛选判断的直接证据缺口；该缺口可在目标期限前补齐。

不可把多个泛化技能加入“补证”清单。优先选择一个能覆盖最核心职责的证据。

### 暂缓或换目标

使用条件：已确认硬门槛不满足，或证据显示关键能力缺口无法在期限内补足。

必须同时给出下一步路径：换层级、换相邻岗位、延后并补资格，或先获取某类可迁移成果。不得只给否决结论。

### 信息不足

使用条件：无法判断硬门槛或核心职责。列出最小补信息请求，不输出乐观或悲观的猜测。

### 最小补信息请求的措辞

- 一轮只请求当前决策最需要的一项或一组信息，不列审问式清单；
- 问具体问题（“这份 JD 的投递截止日期是哪天”），不给开放式提问（“再多介绍点你自己”）；
- 说明为什么需要它（用于核对哪条硬门槛或核心职责），使用者才能判断轻重；
- 使用者已提供的信息足够推进时，不得重复追问。

## 6. 单个行动的设计

好行动满足四个条件：

1. **改变判断**：做完后能支持“可投、补证后投、换目标”之一。
2. **产出具体**：有一份可见交付，不只是一个学习计划。
3. **可验收**：能检查是否包含个人动作、范围、结果、证据来源。
4. **成本受控**：优先选择一次澄清、一份证据页或一个小样本，而不是先投入长期课程。

示例方向：

- 为目标岗位制作一页“要求-证据”对照，但必须包含真实案例和来源；
- 用一个小时向招聘方确认一个关键要求，并记录原话与日期；
- 从现有工作数据中重建一个包含前后对比的客户案例；
- 在真实任务中完成一个小型作品，并请目标岗位从业者按公开标准反馈。

不把“优化简历”“提升沟通能力”“多投递”作为没有定义完成标准的 P0 行动。

## 7. 复查规则

复查必须包含：

- **触发器**：日期、材料补齐、岗位截止、关键回复到达；
- **检查项**：最多三项关键证据或条件；
- **切换规则**：什么情况下维持目标，什么情况下换目标或停止当前动作；
- **记录**：保留上一轮状态和新证据编号，便于看到判断为什么改变；
- **第二轮格式**：新卡表头写“上轮状态 → 本轮状态”及触发变化的那条证据编号；旧编号不复用、不重排，新事实只追加编号。

若复查后仍没有新证据，不重复生成同一建议；改为降低补证成本（把长期课程换成一次澄清或一份证据页）、缩小目标范围（换相邻岗位或降一层级）或换验证路径（请第三方按公开标准反馈）。

## 8. 最终自检

### 常见错误与正确写法

| 错误输出 | 问题 | 正确写法 |
|---|---|---|
| “匹配度 78%，建议投递” | 伪精确评分 | “直接证据覆盖核心职责 A/B，C 项待核验，状态：可投” |
| “你沟通能力不足” | 把证据缺口写成人格/能力判断 | “当前证据不能证明跨部门推动的个人动作” |
| P0 行动写“全面优化简历” | 无完成标准、不可验收 | “补一页客户案例：含个人动作、范围、结果与可核验来源” |
| 用行业常识补 JD 要求 | 编造岗位要求 | “该条 JD 未写明，列为待确认判断，向招聘方确认” |

### 自检清单

- 是否写明了具体岗位或明确说明目标未闭合？
- 是否把使用者自述、可复核证据和分析判断分开？
- 是否有一个会改变决策的待确认判断，而非泛泛问题？
- 是否只有一个 P0 缺口和一个主行动？
- 是否避免“能力评分”“命中率”“保offer”等伪精确结论？
- 复查是否写明触发条件与状态切换规则？
