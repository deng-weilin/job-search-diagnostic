# job-search-diagnostic · 求职诊断器

把“我行不行”改写成可核对的求职决策：对哪个具体岗位、岗位要求是什么、现有事实和证据能证明什么、哪些判断仍未确认、当前最值得解决的一个缺口是什么、用什么动作能在截止时间前改变判断。

**它不代写简历、不打分、不承诺 offer**：不计算匹配度百分比，不把“没有提供证据”说成“没有能力”，一次只给一个优先行动和一条复查规则。

---

## 它解决什么

投递前真正要回答的问题不是“我优不优秀”，而是：**这个岗位的门槛过不过、我的证据覆盖不覆盖核心职责、缺的那一项能不能在截止日前补上。**

| 常见问法 | 这个 skill 怎么处理 |
| --- | --- |
| “我能投吗” | 核对硬门槛 + 核心职责证据覆盖，给条件式状态：可投 / 补证后投递 / 暂缓或换目标 / 信息不足 / 目标未闭合 |
| “帮我对标一下这个 JD” | 简历对标模式：拆简历为条目 → 逐条对标 → 区分“简历没写”（证据缺口）和“经历达不到”（能力缺口） |
| “适合什么岗位” | 目标收敛模式：从已验证资产、不可让步条件、试错成本收敛出 2-3 条可检验目标假设，不评分 |
| “下一步该做什么” | 一个 P0 行动：产出物、完成标准、期限、复查切换规则 |

---

## 三种模式

| 模式 | 进入条件 | 输出 |
| --- | --- | --- |
| 目标收敛 | 没有具体岗位，只有宽泛方向 | 2-3 条目标假设 + 最小验证动作 |
| 岗位诊断 | 有具体岗位和可靠要求 | 六段诊断卡 |
| 简历对标 | 同时提供简历和 JD | 六段诊断卡 + 逐条对标表 |

三种模式共用同一张诊断卡，六个一级标题顺序固定：当前目标 → 事实与证据 → 需要确认的判断 → 主要缺口 → 一个具体行动 → 复查方式。

---

## 关键设计

- **证据分级，不计算总分。** 直接证据 / 书面旁证 / 可追溯自述 / 概括自述 / 空缺五级；简历上的内容默认是自述，不自动当成已核验。
- **两种缺口分开写。** “简历上没有写 / 没有证据”是证据缺口，改简历或补证能解决；“经历本身达不到”是能力或准入缺口，改简历解决不了。混写会误导行动方向。
- **状态是条件式判断，不是能力评级。** 每个状态都写明哪项证据变化会改变它。
- **一个 P0，一个行动。** 行动必须有产出物、完成标准、期限和复查切换规则；“全面优化简历”这种无完成标准的东西不当 P0。
- **JD 原文优先，禁止常识补写。** 关键要求保留原文摘录 + 来源 URL + 检索日期 + 在招状态；检索不到就请使用者粘贴，不编“典型要求”。
- **复查是闭环，不是“再看看”。** 写明触发日期/事件、最多三项检查证据、维持或切换的条件；使用者带新证据回来做第二轮时，新卡标注“上轮状态 → 本轮状态”，旧证据编号不复用；没有新证据不得把同一建议换个说法再讲一遍。
- **替代线索是附录，不是结论。** 仅当结论为“暂缓或换目标”时推送最多 3 条真实在招岗位，只做门槛级核对（学历/专业/年限/证书/地点），不评分不排序。

## 快速开始

这个 skill 由 WorkBuddy 在对话中自动触发，无需命令行。典型用法：

```text
1. 使用者粘贴 JD + 简历        → 简历对标模式，输出逐条对标表与诊断卡
2. 使用者问“我能投这个岗位吗” → 岗位诊断模式
3. 使用者只有方向没有目标      → 目标收敛模式，输出 2-3 条目标假设
4. 使用者带新证据回来          → 第二轮诊断，标注状态变化
```

也可以直接读取本仓库文件，在任何 Agent 框架里复用：

```bash
# 作为 WorkBuddy skill 安装：将整个目录放入 skills/ 下
cp -r job-search-diagnostic ~/.workbuddy/skills/
```

---

## 边界（不可让步）

- 没有具体目标时先收敛目标，不输出笼统能力评分或性格判断；
- 不用百分比、星级或总分表示匹配度；
- 不编造经历、指标、雇主、证书、入职概率或招聘方偏好；
- 一次只给一个优先行动；
- 简历、经历等个人信息只用于本次诊断，不外传。
